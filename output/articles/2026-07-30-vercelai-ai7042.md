# Vercel AI SDK 7.0.42: Security Hardening and Streaming Improvements

Vercel has released version 7.0.42 of its AI SDK, a lightweight TypeScript library for building AI-powered applications. This patch update focuses on critical security enhancements for server-side operations and refinements to the streaming and model configuration systems. The changes reflect growing attention to infrastructure security vulnerabilities in AI application development.

## TL;DR

- **DNS rebinding protection**: Node.js download validation now pins resolved IP addresses at connection time, blocking attacks that route requests through private networks
- **Model configuration flexibility**: Developers can now override model settings on a per-step basis within the `prepareStep` function
- **Streaming metadata preservation**: Empty text deltas during streaming now correctly retain provider-specific metadata
- **Impact**: Improved security posture for production AI applications, greater control over model behavior in multi-step workflows, and more reliable streaming data handling

## Background

The AI SDK ecosystem has grown substantially as organizations integrate large language models into production systems. However, this expansion has brought attention to potential security gaps, particularly around how client applications validate and connect to external services.

DNS rebinding attacks represent a class of vulnerability where attackers manipulate DNS responses to redirect legitimate requests. In the context of Node.js applications, this becomes especially problematic when applications attempt to download models or interact with services that might inadvertently expose access to internal or private networks. Traditional DNS validation happens once during name resolution, but attackers can exploit race conditions or timing windows to redirect subsequent connections.

Additionally, developers building complex AI workflows have expressed the need for finer-grained control over model parameters. The previous architecture sometimes locked certain settings at a global level, reducing flexibility for applications requiring dynamic behavior adjustments across different execution steps.

## How it works

### DNS Rebinding Prevention and Address Pinning

The most significant change in this release addresses a network-level vulnerability affecting server-side operations. When Node.js applications validate downloads—whether for model weights, configuration files, or other resources—they traditionally perform a single DNS lookup and then proceed with the connection.

The updated validation mechanism now implements address pinning: every resolved IP address is validated at the moment of connection, not just at the DNS resolution stage. This approach prevents attackers from performing DNS rebinding attacks where they serve one IP address during the lookup phase and another during the actual connection.

This is particularly critical for AI applications because model files can be large, and connection establishment typically occurs in distinct phases. By pinning addresses, the SDK ensures that even if an attacker controls the DNS infrastructure, they cannot redirect the connection to private services like internal model repositories or metadata endpoints. The implementation validates that resolved addresses don't correspond to private IP ranges, loopback addresses, or other internal network segments.

This protection is especially relevant for organizations using self-hosted model endpoints or internal artifact repositories, where the risk of DNS-based attacks crossing security boundaries is non-negligible.

### Model Configuration Overrides in Step Execution

The `prepareStep` function now accepts configuration overrides that apply to individual invocations. Previously, model settings like temperature, max tokens, and other parameters were primarily configured at initialization time. This created constraints for multi-step workflows where different stages might benefit from different model behaviors.

With this update, developers can now specify model call settings per step, allowing for more nuanced control. For example, a two-stage reasoning pipeline might use conservative settings (lower temperature, structured output) for the first step and more creative settings for subsequent steps, all within the same workflow execution.

### Streaming and Provider Metadata Handling

When streaming text responses from language models, the SDK processes data in incremental chunks. Previously, empty text deltas—updates that don't contain new text but may carry other information—could lose associated provider metadata. This metadata includes model-specific information like token counts, finish reasons, or usage statistics.

The updated streaming implementation now preserves this metadata even when text deltas are empty. This ensures that comprehensive usage information and provider-specific signals remain available throughout the streaming lifecycle, improving observability and billing accuracy.

## Implementation considerations

Organizations using the AI SDK in production should prioritize updating to this version for the security improvements alone. The DNS rebinding protections apply automatically to validated downloads on Node.js environments, requiring no explicit configuration changes.

For applications currently using static model configurations, the new per-step override capability is optional. Teams should evaluate whether their workflows would benefit from dynamic parameter adjustment, particularly in multi-step agent or chain scenarios.

The metadata preservation change is largely transparent, but applications that parse streaming responses should verify they're correctly handling provider metadata in their response processing pipelines.
