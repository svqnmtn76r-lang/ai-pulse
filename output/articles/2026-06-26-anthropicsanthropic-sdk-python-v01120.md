# Anthropic SDK Python v0.112.0: Real-Time System Message Streaming and Enhanced Tooling

Anthropic has released version 0.112.0 of its Python SDK, bringing significant improvements to how developers can handle streaming responses and manage file operations when building applications with Claude. The update introduces native support for system-level message streaming events while addressing critical stability issues in the memory tool subsystem.

## TL;DR

- **System message streaming**: Developers can now receive and process system.message streaming events, enabling real-time visibility into model responses
- **Memory tool improvements**: Directory creation now handles permissions correctly, fixing a significant reliability issue for applications using persistent storage
- **Profile tracking**: The SDK now supports sending User Profile IDs in request headers, improving analytics and usage tracking capabilities
- **Refusal handling**: Enhanced support for categorizing model refusals provides better control over content moderation workflows

## Background

Python SDK updates for AI platforms typically focus on three areas: expanding the capabilities of the underlying API, fixing operational issues that impact production applications, and improving the developer experience. The v0.112.0 release addresses all three, but the most impactful addition is the streaming events support.

Real-time streaming has become increasingly important in AI applications because it allows developers to display partial responses to users immediately, rather than waiting for complete model outputs. This creates more responsive user experiences and enables progressive disclosure of information. However, streaming implementations require careful handling of event types and state management.

The memory tool fix addresses a more subtle but equally important problem: applications that persist data to disk can fail unexpectedly when directory structures don't exist or have incorrect permissions. This is the kind of issue that only appears in production deployments under specific conditions, making it particularly valuable to address in a maintenance release.

## How it works

### System Message Streaming Events

The primary feature in this release adds support for `system.message` streaming events. In Anthropic's architecture, streaming responses from Claude are delivered as a series of events that applications must parse and handle appropriately. Previously, the SDK primarily supported content streaming events—the actual text generated by the model.

System message events serve a different purpose: they communicate metadata about the response generation process itself. This might include information about how the model structured its reasoning, which tools it considered invoking, or details about how it applied safety guidelines. By exposing these events to developers, the SDK enables more sophisticated applications that can react to or log this system-level information in real time.

Implementing this required changes to the client's event handling pipeline. The SDK now recognizes and surfaces `system.message` event types through the same streaming interface developers already use, maintaining API consistency while expanding functionality. Applications can subscribe to these events and process them alongside content events, creating a complete picture of the generation process.

### Memory Tool Directory Permissions

The memory tool is a utility that allows Claude applications to persist information across conversations. It's particularly valuable for multi-turn interactions where the model needs to remember context from previous exchanges. The tool writes data to the file system, but previous versions had a subtle bug: when creating parent directories, the SDK didn't explicitly set correct permissions.

This could cause two problems. First, directories created with overly permissive settings could represent a security risk in shared environments. Second, directories created with insufficiently permissive settings could prevent the application from reading or modifying the memory data later. The v0.112.0 release fixes this by explicitly configuring directory permissions during creation, ensuring both security and functionality.

This fix is particularly important for applications deployed in containerized or cloud environments, where file permission issues often only manifest under specific deployment configurations—making them difficult to debug and reproduce locally.

### Enhanced Request Headers and Refusal Categorization

Two additional improvements round out the release. The SDK now supports sending User Profile IDs in request headers, enabling Anthropic's backend systems to track usage patterns and associate API requests with specific user accounts. This is valuable for applications that manage multiple end users and need granular usage metrics.

The support for new refusal categories provides more nuanced control over how the model declines certain requests. Rather than a simple yes/no on whether the model will respond, developers can now see which category of refusal was applied—whether the model declined due to safety guidelines, content policy, or other constraints. This enables more intelligent fallback logic and better user communication about why certain requests cannot be fulfilled.

## What happens next

Version 0.112.0 represents incremental but important progress in the Anthropic SDK. Developers currently using streaming features should review whether system message events add value to their applications. Teams deploying memory-dependent applications should prioritize upgrading to ensure directory permissions work correctly across all environments.

For new projects, this version provides a more complete toolkit for building sophisticated AI applications. The streaming improvements and corrected file handling reduce the likelihood of subtle bugs appearing in production, while the refusal categorization enables more intelligent application logic around model limitations.

The release maintains backward compatibility, so existing applications continue working without modification. However, the new capabilities are worth exploring—particularly for applications that need real-time visibility into model behavior or persistent cross-session memory.
