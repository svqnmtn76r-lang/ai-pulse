# Vercel AI SDK 6.0.220: Bug Fixes for Tool Integration and Streaming

Vercel has released version 6.0.220 of its AI SDK, a minor patch update that addresses two important issues affecting developers building AI applications. The release focuses on improving the reliability of tool calling workflows and JSON extraction from streamed responses—two critical features for production AI systems.

## TL;DR

- **Tool ordering fix**: The SDK now correctly preserves the order of tool results when converting AI model outputs into standardized response messages, preventing potential logic errors in complex multi-tool workflows.
- **JSON streaming refinement**: A whitespace handling bug in `extractJsonMiddleware` has been resolved, ensuring cleaner final text output when parsing JSON from streamed responses.
- **Dependency updates**: Supporting library upgrades maintain compatibility and security across the SDK ecosystem.
- **Impact**: Developers using tool calling or JSON extraction from streams will experience more predictable and reliable behavior, reducing edge cases and debugging overhead.

## Background

Tool calling has become a fundamental pattern in modern AI applications, enabling language models to interact with external APIs, databases, and services. When an AI model generates multiple tool calls in sequence, maintaining their order is essential—the downstream system needs to know which tool was invoked first, second, and so on, to properly execute and chain operations.

Similarly, streaming JSON responses from AI models has become increasingly common as developers seek to extract structured data from real-time model outputs. Middleware components that parse and extract JSON during streaming must carefully handle formatting edge cases, particularly when markdown fence markers (triple backticks) are used to delimit JSON blocks in the model's response.

The Vercel AI SDK provides abstractions and utilities for both patterns, but like any production software, occasional refinements are needed as edge cases surface in real-world usage.

## How it works

### Tool Result Ordering in Message Conversion

When an AI model processes a prompt containing tool use instructions, it can invoke multiple tools in a single response. The model returns these calls with metadata indicating their sequence. The SDK's message conversion system takes this raw output and transforms it into a standardized response format for downstream processing.

The fix in this patch ensures that when converting these model outputs to message objects, tool results maintain their original invocation order. This matters because consuming applications often rely on sequential tool execution or chaining—where one tool's output feeds into another's input. If results arrive out of order, dependent operations may fail or produce incorrect results. For instance, if a model calls a database query tool followed by a data transformation tool, receiving the transformation results before the query results could cause failures or logical errors.

This ordering preservation happens during the internal conversion phase, before the response reaches application code, making it a transparent but crucial fix for multi-tool workflows.

### JSON Middleware Whitespace Handling

The `extractJsonMiddleware` component is designed to extract JSON objects or arrays from streaming text responses, particularly when models wrap JSON in markdown code blocks. Models sometimes output responses like:

```
Here's your data:
```json
{"key": "value"}
```
```

The middleware strips the markdown fence markers and extracts the JSON content. However, the previous implementation had a subtle bug: when no markdown fence prefix was detected in the streamed output, any leading whitespace that should have been part of the suffix text was being incorrectly preserved in the final streamed result.

This created scenarios where the final text chunk contained unexpected whitespace, potentially affecting downstream text processing, display formatting, or further parsing. The fix ensures that whitespace is handled consistently whether or not markdown fences are present, resulting in cleaner output that matches expected formatting.
