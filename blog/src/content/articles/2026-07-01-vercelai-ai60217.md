# Vercel AI SDK 6.0.217: Enhanced Video Generation with Direct Frame Control

Vercel has released version 6.0.217 of its AI SDK, introducing first-class support for video generation parameters that give developers more granular control over frame-based content creation. This patch update streamlines how developers can pass frame images and input references directly to video generation models, reducing complexity in multimedia AI workflows.

- **Input References**: New `inputReferences` parameter enables cleaner specification of reference materials for video models

- **Impact**: Developers building video generation features get a more intuitive interface with less boilerplate code and fewer integration headaches

## Background

Video generation has become increasingly important in AI applications, with models like Runway, Pika, and others supporting frame-conditional generation—the ability to guide video creation using reference images or keyframes. However, the Vercel AI SDK previously lacked dedicated parameters for passing these inputs, forcing developers to work around the SDK's structure or use lower-level APIs directly.

This gap created friction in the developer experience. Teams building video editing tools, creative applications, or AI-powered content generation needed workarounds to pass frame data, often relying on custom implementations or SDK extension patterns. By formalizing these as first-class options, Vercel removes the friction and signals the importance of video as a first-tier AI capability alongside text and image generation.

## How it works

### Frame Images: Native Support for Sequential Visual Input

The new `frameImages` call option allows developers to pass arrays of image data directly into video generation requests. Rather than constructing manual request bodies or using provider-specific APIs, developers can now leverage the SDK's standard patterns for handling visual inputs.

This matters because video generation models often benefit from frame conditioning—whether that's keyframe interpolation, style transfer across frames, or motion guidance. Previously, developers had to understand the underlying model provider's API and manually serialize image data. Now, the SDK handles this transparently. The implementation maintains consistency with how the SDK treats images in other contexts (like vision models), creating a cohesive developer experience. Type definitions ensure developers get autocomplete and compile-time safety, while documentation examples guide proper usage patterns.

### Input References: Flexible Guidance Parameters

The companion `inputReferences` parameter provides a broader mechanism for specifying reference materials that guide video generation without being frame-sequential. This might include style references, motion capture data, or other conditioning inputs that don't fit the frame-by-frame model.

This distinction matters because not all reference data follows a temporal sequence. Some video generation scenarios require style guidance, object tracking references, or other non-sequential conditioning. By providing `inputReferences` as a dedicated option, the SDK accommodates these use cases while keeping the API intelligible. Developers can distinguish between "these are frames that will appear in the output" and "these are references that will influence the output," leading to clearer, more maintainable code.

### Dependency Updates Ensure Ecosystem Consistency

The patch includes coordinated updates across the AI SDK's component libraries: `@ai-sdk/gateway` (3.0.141), `@ai-sdk/provider` (3.0.13), and `@ai-sdk/provider-utils` (4.0.34). These synchronized updates ensure that video generation parameters flow correctly through the entire abstraction layer—from the SDK's public API down to provider adapters that interface with actual model APIs.
