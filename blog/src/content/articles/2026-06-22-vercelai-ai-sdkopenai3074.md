# Vercel's AI SDK Gets Enhanced Token Usage Tracking for OpenAI Models

Vercel has released version 3.0.74 of its OpenAI integration for the AI SDK, introducing more granular visibility into how tokens are consumed when using OpenAI's APIs through the Responses API. This update addresses a growing need for developers to understand and optimize token usage across complex AI applications, where different types of tokens—input, output, and cached—are charged at different rates.

## TL;DR

- **Token usage orchestration**: The update adds detailed breakdowns of token consumption across different stages of API responses, moving beyond simple input/output counts
- **Responses API integration**: These enhanced metrics are specifically available when using OpenAI's Responses API, part of their newer inference optimization framework
- **Impact**: Developers can now identify optimization opportunities in their AI pipelines and better predict costs for production deployments

## Background

OpenAI's pricing model has become increasingly complex. Beyond standard input and output tokens, the platform now offers prompt caching, which reduces costs for repeated context, and distinguishes between different token types in responses. As AI applications grow more sophisticated—involving multi-step reasoning, tool use, and complex workflows—developers have struggled to attribute token costs to specific operations.

The AI SDK, maintained by Vercel, serves as a JavaScript/TypeScript abstraction layer over various LLM providers including OpenAI. Its goal is to standardize how developers interact with different models and manage common patterns like streaming, function calling, and response formatting. However, without detailed token usage information flowing back through these abstractions, developers were left blind to where their API costs were actually accumulating.

This limitation becomes particularly problematic in orchestration scenarios—where an application makes multiple sequential or parallel API calls, potentially with different configurations. Understanding which step in a workflow consumes the most tokens is essential for optimization.

## How it works

### Token Usage Details in Responses

The patch introduces enhanced usage telemetry to the Responses API integration. Rather than returning aggregate token counts, the updated implementation now surfaces "orchestration token usage details"—a structured breakdown of how tokens are consumed across different components of a response.

In practical terms, when a developer makes an API call through the AI SDK's OpenAI integration, the returned object now includes more granular usage information. This typically includes separate counts for: tokens in the initial prompt, tokens in cached content (if prompt caching is enabled), tokens generated by the model, and any additional overhead tokens from special features like tool use or extended thinking modes.

This granularity matters because it allows developers to understand exactly where optimization efforts will have the most impact. If a workflow is token-heavy due to a long system prompt or repeated context, caching becomes attractive. If output tokens dominate, techniques like response summarization or structured extraction become priorities.

### Integration with OpenAI's Responses API

OpenAI's Responses API represents a shift toward more structured, deterministic outputs from language models. Unlike the chat completions API, which returns free-form text, the Responses API enforces output schemas and provides more predictable token usage patterns. This makes it ideal for applications building on top of AI—like code generation tools, data extraction systems, or structured analysis platforms.

By enriching the token usage data returned from the Responses API, the AI SDK makes this optimization-friendly endpoint even more valuable. Developers can now A/B test different prompt strategies, schema designs, or model parameters while seeing exactly how each change affects token consumption and therefore cost.

### Implementation considerations

This enhancement is backward compatible—existing code continues to work unchanged. The additional usage details are simply added to the response objects returned by relevant API calls. Developers can opt into using this information by inspecting the usage properties on responses, without requiring any modifications to how they invoke the SDK.

The implementation leverages OpenAI's existing usage telemetry returned in API responses, simply surfacing it through the AI SDK's abstraction with more structured organization. This means there's minimal performance overhead—the data is already being transmitted, just repackaged for clearer interpretation.

## Practical implications

For teams deploying AI features into production, this update offers concrete benefits. Cost forecasting becomes more accurate when you understand token distribution across your workflows.
