# Vercel AI SDK 7.0.35: Improved Error Handling and Streaming Reliability

Vercel has released version 7.0.35 of its popular AI SDK, a TypeScript library that simplifies building AI-powered applications. This patch release focuses on critical improvements to streaming error management and introduces per-step timeout controls for generation workflows—enhancements that address real-world reliability challenges developers face when integrating AI features into production applications.

## TL;DR

- **Stream Error Propagation**: The SDK now properly returns promises from response piping operations, allowing developers to catch and handle errors that occur during streaming reads and writes—a crucial fix for production stability.
- **Per-Step Timeouts**: New granular timeout controls let developers set first-content timeouts on individual generation steps, providing finer control over streaming behavior in multi-step workflows.
- **Dependency Updates**: Gateway SDK updated to version 4.0.27, ensuring compatibility with the latest provider infrastructure.
- **Impact**: These changes reduce silent failures in streaming scenarios and give developers better control over timeout behavior in complex AI workflows, particularly important for applications handling user-facing streaming interactions.

## Background

Streaming responses have become central to modern AI applications. Unlike traditional request-response patterns, streaming allows users to see AI model outputs appear incrementally—creating a more responsive and engaging experience. However, streaming introduces complexity: errors can occur mid-stream, network issues may interrupt data flow, and timeout behavior becomes harder to predict in complex workflows.

The Vercel AI SDK emerged to abstract away much of this complexity, providing a unified interface across multiple AI providers (OpenAI, Anthropic, Google, etc.). However, as developers deployed streaming AI features to production, two pain points became evident: first, promise-based error handling for streams wasn't consistently implemented, meaning errors during streaming could go unnoticed; second, applications with multi-step generation workflows needed fine-grained control over when to timeout individual steps rather than applying blanket timeout rules.

## How it works

### Proper Promise Handling for Stream Operations

The core improvement in this release addresses a subtle but critical issue in JavaScript streaming patterns. When you pipe a response stream—moving data from a source to a destination—errors can occur at two points: during reading from the source or writing to the destination.

Previously, the SDK's response piping operations weren't consistently returning promises that callers could await. This meant developers couldn't reliably catch errors like network interruptions, connection resets, or destination write failures. The fix ensures that piping operations return catchable promises, enabling code like this:

```typescript
try {
  await pipeResponse(sourceStream, destinationStream);
} catch (error) {
  // Handle stream errors gracefully
}
```

This pattern is especially critical for serverless environments and edge deployments, where transient network errors are more common. By making error states observable, developers can implement retry logic, fallback mechanisms, or user-facing error messages appropriately.

### Per-Step First Content Timeouts for Streaming

The second major enhancement introduces more granular control over timeout behavior in streaming workflows. "First content timeout" refers to the maximum time a client will wait to receive the first chunk of data from a streaming response—a critical metric for user experience.

Previously, developers configured timeouts globally. This works for simple use cases, but falls apart when workflows involve multiple sequential generation steps. Perhaps step one (generating a query plan) should timeout quickly since it's simple, while step two (generating comprehensive responses) might legitimately need more time.

The new per-step timeout feature allows configuration at the individual generation level:

```typescript
// Step 1: Quick operation
const plan = await generatePlan(input, { 
  firstContentTimeout: 2000 
});

// Step 2: Longer operation
const response = await generateResponse(plan, { 
  firstContentTimeout: 10000 
});
```

This flexibility prevents unnecessary timeouts on lengthy operations while keeping responsive operations from hanging indefinitely. It's particularly valuable in agentic workflows where different steps have different computational complexity.

### Updated Gateway Infrastructure

The patch also updates the AI Gateway SDK to version 4.0.27, Vercel's infrastructure service that provides rate limiting, caching, and monitoring for AI API calls. This ensures the core SDK works with the latest gateway features and security patches, maintaining compatibility as Vercel's AI platform evolves.
