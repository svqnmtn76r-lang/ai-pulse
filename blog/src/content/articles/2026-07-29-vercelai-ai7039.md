# Vercel's AI Library Graduates Text Repair Feature to Stable Status

Vercel has released version 7.0.39 of its AI SDK, marking an important milestone for developers working with language models. The update promotes the `repairText` option from experimental status to a fully stable feature across two core functions: `generateObject` and `streamObject`. This graduation reflects the maturity of the functionality after a period of refinement and real-world testing.

- **Text Repair Stabilization**: The `repairText` option moves from experimental to stable, improving reliability for structured data generation
- **Backward Compatibility**: Legacy code using the deprecated `experimental_repairText` alias continues to work without breaking
- **Dependency Updates**: The release includes updates to provider utilities and gateway components, ensuring better integration with AI model providers
- **Impact**: Developers can now confidently use text repair in production environments with guaranteed API stability and support

## Background

Generating structured data from language models has long been a challenging problem. Models like GPT-4 excel at producing natural language but sometimes struggle to adhere strictly to JSON schemas or other structured formats. They may insert extra commas, omit required fields, or include trailing content that breaks parsing.

The text repair feature was introduced as an experimental capability to address this gap. It acts as a safety net when language models produce output that's close to the desired format but not quite valid. Rather than failing entirely, the repair mechanism attempts to fix common formatting issues, making the output suitable for structured parsing.

This experimental period allowed Vercel's team to gather feedback from developers using the feature in real applications, identify edge cases, and refine the underlying logic. The graduation to stable status signals confidence in the implementation's reliability and performance.

## How it works

### The Repair Mechanism

Text repair operates as a post-processing layer for object generation. When you call `generateObject` or `streamObject`, the language model returns output intended to match a specific schema. The repair mechanism examines this output and identifies common formatting problems—unclosed brackets, missing commas between properties, or invalid escape sequences.

Rather than rejecting malformed responses outright, the repair logic applies corrective transformations. This approach significantly improves the success rate of structured generation, particularly with less capable models or when dealing with complex schemas. The feature works transparently, requiring no additional setup beyond enabling the option.

### API Changes and Migration

The primary change in this release involves the naming convention. Previously, developers would set `experimental_repairText: true` when calling these functions. This naming clearly indicated the feature's unstable status, which was appropriate during development but became cumbersome as the feature matured.

Version 7.0.39 introduces `repairText` as the canonical option name. For backward compatibility, the old `experimental_repairText` name continues to function, but Vercel marks it as deprecated. This approach prevents breaking existing applications while encouraging developers to migrate to the new naming convention. No functional changes accompany the renaming—the underlying behavior remains identical.

### Dependency Chain Updates

Beyond the text repair promotion, this release includes updates to two critical dependencies: `@ai-sdk/provider-utils` advances to version 5.0.14, and `@ai-sdk/gateway` reaches version 4.0.30. These utilities form the infrastructure that enables the AI SDK to communicate with various language model providers.

Provider utilities handle the abstraction layer between Vercel's API and different model vendors. The gateway component manages routing, rate limiting, and authentication across multiple providers. While the release notes don't detail specific improvements in these dependencies, their inclusion suggests refinements to compatibility, performance, or security aspects of the provider integration layer.
