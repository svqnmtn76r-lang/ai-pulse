# Vercel AI SDK 7.0.8: First-Class Video Generation Support Now Available

Vercel has released version 7.0.8 of its popular AI SDK, introducing dedicated support for video generation workflows. The update adds native handling for frame images and input references—two critical features that developers have previously worked around with workarounds. This patch represents a maturing of the SDK's multimodal capabilities, signaling Vercel's commitment to supporting emerging AI use cases beyond text and static images.

## TL;DR

- **frameImages option**: Direct API support for specifying video frames during generation, eliminating previous workarounds
- **inputReferences parameter**: Native handling of reference materials that inform video output, now exposed as a first-class call option
- **Dependency updates**: Three core packages bumped to maintain compatibility and stability across the AI SDK ecosystem
- **Impact**: Developers building video AI applications can now use cleaner, more maintainable code with better type safety and official support

## Background

The AI SDK ecosystem has evolved substantially over the past year as generative AI capabilities expanded beyond text completion and image generation. Video generation emerged as a natural next frontier, with services like Runway, Pika Labs, and others launching APIs for creating videos from text prompts or images.

However, the initial releases of tools supporting video generation often required developers to manually construct request payloads or use generic parameters that didn't specifically account for video-specific requirements. The SDK lacked explicit, first-class support for concepts like sequential frame specifications or reference material handling—features that are foundational to how modern video generation models work.

This created friction for developers. Teams building video features had to either work directly with underlying provider APIs, forgoing the SDK's convenience layer, or write custom abstraction code to map video-specific parameters into the SDK's existing structure. The 7.0.8 release addresses this gap by promoting video-specific functionality from implicit to explicit API surface.

## How it works

### Understanding frameImages and its purpose

Video generation differs fundamentally from image generation in that it produces temporal sequences rather than static outputs. The `frameImages` option allows developers to specify a collection of image frames that guide or condition the video generation process.

In practical terms, this might mean providing keyframes that establish the visual direction of the output, or reference images that define style, composition, or character appearance. Rather than requiring developers to bundle these as generic "inputs," the SDK now explicitly recognizes them as frame data with appropriate handling for multiframe scenarios.

The first-class treatment means the parameter receives proper typing, validation, and documentation. Developers get IDE autocomplete suggestions, compile-time type checking, and clear documentation of expected formats. Behind the scenes, the SDK handles the serialization and transmission of multiple images correctly for video generation endpoints.

### Understanding inputReferences

The `inputReferences` parameter serves a complementary purpose. While `frameImages` typically represents visual guidance material, `inputReferences` encompasses broader contextual information that informs generation—this might include text descriptions, style guides, narrative elements, or other metadata that shapes the video output without necessarily being visual frames themselves.

By exposing this as a dedicated call option, Vercel signals that reference material is a legitimate, expected input to video workflows, not an afterthought. Providers can now reliably expect this parameter to be present and properly formatted, enabling more sophisticated video generation pipelines.

### Dependency ecosystem updates

The patch also bumps three related packages: @ai-sdk/provider (4.0.1), @ai-sdk/gateway (4.0.6), and @ai-sdk/provider-utils (5.0.2). These updates ensure that the video generation features work correctly across the broader SDK ecosystem. The version increments suggest meaningful changes—provider likely includes type definitions and interfaces for the new parameters, gateway probably adds routing or protocol support for video-specific requests, and provider-utils likely includes utility functions for handling frame and reference data.

This release positions the SDK for broader adoption among developers working with video AI. As video generation becomes more commonplace in applications, having native SDK support reduces friction and improves code quality.

The next logical extensions might include explicit support for video-specific models and providers beyond the current set, additional parameters for controlling video length or frame rate through first-class options rather than provider-specific workarounds, and potentially built-in utilities for handling frame extraction, image composition, or video assembly workflows.
